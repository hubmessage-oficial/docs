## Envelope do evento

Toda requisição enviada ao seu webhook tem a seguinte estrutura de topo:

```json
{
  "message": { ... },
  "messageEventType": "NEW_MESSAGE"
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `message` | object | Objeto completo da mensagem |
| `messageEventType` | string | Tipo do evento, quando presente. Esse campo pode não ser enviado em todos os eventos. |

## Campos comuns da mensagem

Todos os payloads compartilham os mesmos campos no objeto `message`, independente do tipo de conteúdo:

| Campo | Tipo | Descrição |
|---|---|---|
| `_id` | string | ID único da mensagem |
| `tenant` | string | ID do workspace |
| `tenant_owner` | string | E-mail do dono do workspace |
| `channel_id` | string | ID do canal que recebeu/enviou a mensagem |
| `created_by` | string | Origem interna da mensagem |
| `created` | number | Timestamp de criação (epoch ms) |
| `metadata.from_api` | boolean | `true` quando enviada via API |
| `metadata.from_me` | boolean | `true` quando enviada pelo negócio; `false` quando recebida do contato |
| `metadata.middleware` | string | Plataforma do canal (ex: `"META_WHATSAPP"`) |
| `metadata.forwarded` | boolean | `true` se a mensagem foi encaminhada |
| `sender.identifier` | string | Identificador de quem enviou |
| `sender.name` | string | Nome de quem enviou |
| `recipient.identifier` | string | Identificador do destinatário desta mensagem. O valor depende do canal e da direção (`metadata.from_me`); não assuma que ele seja sempre o cliente. |
| `contents` | array | Conteúdos textuais e interativos da mensagem |
| `attachments` | array | Anexos de mídia (imagem, áudio, vídeo, sticker) |
| `media_webhook_processed` | boolean | Controle interno de processamento de mídia |

<Note>
  Os exemplos desta página usam mensagens do **WhatsApp Business** (`metadata.middleware: "META_WHATSAPP"`). Não use o formato ou o papel do `recipient.identifier` desses exemplos para outros canais: o identificador varia conforme a plataforma e a direção da mensagem.
</Note>

## Payload do Instagram

O Hub Message normaliza o webhook do Instagram para o mesmo envelope usado pelos demais canais. A Meta envia os identificadores como `sender.id` e `recipient.id`; no webhook do Hub Message eles aparecem como `message.sender.identifier` e `message.recipient.identifier`.

Em uma mensagem recebida do cliente (`metadata.from_me: false`), o identificador que deve ser guardado para responder é `message.sender.identifier`. O `message.recipient.identifier` é o identificador da conta profissional que recebeu a mensagem.

```json
{
  "message": {
    "_id": "...",
    "tenant": "",
    "tenant_owner": "",
    "channel_id": "019FB4257427730B82F4E37B11B11382",
    "created_by": "CONWAY",
    "created": 1785968840699,
    "metadata": {
      "@class": ".Metadata",
      "forwarded": false,
      "from_api": false,
      "from_me": false,
      "middleware": "META_INSTAGRAM",
      "moment": 1785968838347
    },
    "sender": {
      "@class": ".Sender",
      "identifier": "1073673115189819"
    },
    "recipient": {
      "@class": ".Recipient",
      "identifier": "17841437106730710"
    },
    "contents": [
      {
        "@class": ".TextContent",
        "internal_information": {
          "integration_id": "..."
        },
        "message": "opa",
        "type": "TEXT"
      }
    ],
    "attachments": [],
    "actions": [],
    "media_webhook_processed": false
  }
}
```

Neste exemplo, `1073673115189819` é o ID do cliente e `17841437106730710` é o ID da conta profissional. O campo `metadata.from_me` informa se a mensagem foi marcada como enviada pelo negócio; para responder ao cliente a partir de um evento de recebimento, use o `message.sender.identifier` recebido.

### Particularidades de mídia

No canal do Instagram, as mensagens podem aparecer no webhook com estas representações:

| Mensagem enviada | Representação no webhook | Observação |
|---|---|---|
| Texto | `contents[0].type: "TEXT"` | O texto fica em `contents[0].message`. |
| Imagem | `attachments[0].type: "IMAGE"` | Pode incluir `url`, `thumbnail_url` e `caption`. |
| Documento | `attachments[0].type: "DOCUMENT"` | O anexo é entregue como documento. |
| Sticker | `attachments[0].type: "IMAGE"` | O Instagram converte a figurinha em imagem; pode incluir `thumbnail_url`. |
| Áudio `.m4a` | `attachments[0].type: "AUDIO"` | A URL recebida pode ser normalizada para um arquivo `.mp3`. |

Áudio `.ogg` não é entregue como evento relacionado no webhook. Use os formatos de áudio documentados como suportados pelo Instagram.

### Corpo compactado

Alguns eventos podem chegar com o header HTTP `Content-Encoding: gzip`. O consumidor deve respeitar esse header e descompactar o corpo antes de interpretar o JSON. Frameworks HTTP que fazem a descompressão automaticamente já entregam o body pronto para leitura.

O campo `messageEventType` é opcional e pode não ser enviado em eventos do Instagram. Quando ele não estiver presente, identifique o tipo do conteúdo em `contents[].type` ou `attachments[].type`.

## Tipos de conteúdo

O campo que diferencia o tipo de mensagem é o `@class` dentro de cada item de `contents` ou `attachments`, combinado com o campo `type`.
