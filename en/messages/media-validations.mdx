## How it works

When you call `POST /v1/channels/{channelId}/messages` with an attachment, for **Meta WhatsApp** channels Hub Message processes the media **synchronously** (within the request itself):

<Steps>
  <Step title="Downloads the media">
    Downloads the file from the provided `url` (or decodes a base64 _data URL_).
  </Step>
  <Step title="Validates">
    Checks format, size and caption.
  </Step>
  <Step title="Converts/normalizes">
    Adjusts to a format accepted by Meta, when needed.
  </Step>
  <Step title="Sends">
    Uploads the final file and sends it to WhatsApp.
  </Step>
</Steps>

If anything is outside the rules, the request **fails immediately with an HTTP error**. Every error carries a **stable `subCode`** — handle your flow by it, **never** by the `message` text (which is human-facing and may change or be translated).

<Note>
  For channels that are **not** Meta WhatsApp, the `url` is passed through without conversion or validation.
</Note>

## Accepted formats and limits

| Type | Accepted **input** formats | Delivered to Meta as | Max size (final file) |
|------|----------------------------|----------------------|------------------------|
| **Image** | JPEG, PNG, BMP, TIFF, GIF, WebP | JPEG or PNG (JPEG/PNG pass through; others are converted to JPEG) | **5 MB** |
| **Sticker** | WebP, PNG, JPEG, GIF, BMP, TIFF | WebP 512×512 | static **100 KB** / animated **500 KB** |
| **Audio** | AAC, AMR, MP3, M4A, OGG, OPUS, WAV, FLAC | OGG/Opus (AMR is passed through) | **16 MB** |
| **Video** | MP4, 3GP, MKV, AVI, MOV | MP4 (H.264/AAC); 3GP passed through | **16 MB** |
| **Document** | TXT, XLS, XLSX, DOC, DOCX, PPT, PPTX, PDF | same format (DOC/DOCX are converted to PDF) | **100 MB** |

**Notes:**

- **Image:** Meta only accepts JPEG/PNG. Sending BMP/TIFF/GIF/WebP is allowed — Hub Message converts to JPEG (for GIF, it uses the first frame).
- **Sticker:** any image is normalized to **WebP 512×512**. The **static limit is 100 KB**; animated (from GIF/WebP/video) is **500 KB**.
- **Size:** the limit is validated on the **final file** (after conversion). In addition, the **input** file cannot exceed **100 MB**.
- **Caption:** image, video and document accept a caption of at most **1024 characters**.
- **URL:** must be an accessible `http(s)://` URL **or** a base64 _data URL_ (`data:<mime>;base64,...`).

## Error codes (`subCode`)

Error response format:

```json
{
  "timestamp": "2026-07-13T18:20:00Z",
  "code": "VALIDATION_ERROR",
  "subCode": "MEDIA_MIME_NOT_ALLOWED",
  "message": "Media type not allowed for IMAGE: image/svg+xml"
}
```

| `subCode` | HTTP | When it happens | How to resolve |
|-----------|------|-----------------|----------------|
| `MEDIA_URL_REQUIRED` | 400 | Attachment without `url`/media | Provide the attachment `url` |
| `MEDIA_INVALID_URL` | 400 | `url` not `http(s)://` or data URL | Send a valid (https) URL or a base64 data URL |
| `MEDIA_INVALID_DATA_URL` | 400 | Malformed base64 data URL | Check the `data:<mime>;base64,<content>` format |
| `MEDIA_MIME_NOT_ALLOWED` | 400 | Format not accepted for that attachment type | Use one of the formats in the table above |
| `MEDIA_TOO_LARGE` | 400 | File (input or final) above the limit | Reduce the media size/quality |
| `MEDIA_CAPTION_TOO_LONG` | 400 | Caption longer than 1024 characters | Shorten the caption |
| `MEDIA_UNSUPPORTED_ATTACHMENT` | 400 | Attachment type not supported for conversion | Use image, sticker, audio, video or document |
| `MEDIA_DOWNLOAD_FAILED` | 502 | Could not download the media from the `url` | Make sure the URL is public and accessible |
| `MEDIA_CONVERSION_FAILED` | 502 | Failed to convert the media | Retry; if it persists, contact support |
| `MEDIA_UPLOAD_FAILED` | 502 | Failed to store the media | Retry; if it persists, contact support |
| `MEDIA_PROCESSING_FAILED` | 502 | Unexpected processing failure | Retry; if it persists, contact support |

- **400** = problem with what was sent (fix and resend).
- **502** = temporary technical failure while processing/delivering (resend; if it persists, contact support).

## Compatibility notes

- The `subCode` field only appears in media errors; other errors keep `{ timestamp, code, message }`.
- Source of Meta's rules: WhatsApp Cloud API — [Supported Media Types](https://developers.facebook.com/docs/whatsapp/cloud-api/reference/media/).
- Known limitation: for **WebP**-sourced stickers, Hub Message applies the **500 KB** (animated) limit; Meta may reject a **static** WebP above **100 KB**. Prefer sending static stickers already optimized (≤ 100 KB).
